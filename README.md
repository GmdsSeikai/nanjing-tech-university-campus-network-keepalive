# 南京工业大学校园网保活工具

**Nanjing Tech University Campus Network Keepalive Tool**

适配南京工业大学 Dr.COM 门户的 Windows 桌面工具，提供一键登录、自动保活与到期重新认证。支持中国移动账号，以及电脑通过宿舍路由器接入校园网的场景。电脑和程序持续运行时，默认每 30 秒检测外网连通性，确认需要认证后自动恢复。

公开仓库：[GmdsSeikai/nanjing-tech-university-campus-network-keepalive](https://github.com/GmdsSeikai/nanjing-tech-university-campus-network-keepalive)。

## 功能

- **一键登录**：使用学号和统一身份认证密码完成校园网认证，自动处理中国移动账号后缀。
- **自动保活与断线重连**：定时发送小体积 HTTP 探测；确认认证到期后重新登录，临时失败按退避间隔重试。
- **宿舍路由器认证**：从学校门户获取当前出口身份，避免把电脑的局域网 IP/MAC 当作校园网认证身份。
- **系统托盘**：关闭窗口后继续运行，可从托盘恢复主界面或退出。
- **单实例运行**：图形界面和命令行模式共用锁，避免同时启动多个认证循环。
- **本地配置与日志**：Windows DPAPI 加密保存密码，日志记录检测、认证、退避和恢复状态。
- **命令行模式**：支持 `--monitor` 持续监控和 `--once` 单次检测。

连通性探测不能保证延长校园网强制到期会话；工具通过到期后重新认证恢复连接。电脑睡眠、断电、退出程序或断开校园网期间无法保活。

## 使用前准备

1. 使用 Windows 电脑。仓库内的 EXE 为 64 位 Windows 程序；源码也依赖 Windows DPAPI、托盘和单实例机制。
2. 将电脑连接到校园网，或连接已接入校园网的宿舍路由器。
3. 准备学号、统一身份认证密码和对应运营商的已绑定套餐。
4. 如果尚未办理或绑定套餐，先完成学校和运营商要求的绑定流程。

学校账号、密码和套餐说明可参考 [南京工业大学学生宿舍上网指南](https://network.njtech.edu.cn/info/1035/1421.htm)。中国移动是本项目已现场验证自动重新认证的服务；界面同时保留校园用户、校园电信、校园联通和校园其他选项，其他套餐应按自己的账号情况选择并验证。

## 下载与运行

普通使用者直接运行 EXE，无需安装 Python，也无需启动远程控制服务器、手机程序或修改路由器固件。登录与保活无需管理员权限。

1. 打开 [CampusNetLogin.exe 下载页面](https://github.com/GmdsSeikai/nanjing-tech-university-campus-network-keepalive/blob/main/release/CampusNetLogin.exe)，点击 **Download raw file** 下载。也可使用 [EXE 直接下载链接](https://raw.githubusercontent.com/GmdsSeikai/nanjing-tech-university-campus-network-keepalive/main/release/CampusNetLogin.exe)。
2. 将文件放到方便查找的位置，例如自己创建的工具文件夹。
3. 双击 `CampusNetLogin.exe`，打开“校园网一键登录”窗口。

也可以在仓库首页选择 **Code → Download ZIP**，解压后运行 `release/CampusNetLogin.exe`。配置保存在 Windows 用户目录，移动 EXE 不会改变配置位置。

## 首次配置：以中国移动和宿舍路由器为例

### 1. 填写账号

在“登录”选项卡的“账号设置”区域填写：

| 设置项 | 填写方式 |
| --- | --- |
| 用户名 | 填自己的原始学号 |
| 密码 | 填自己的统一身份认证密码 |
| 服务 | 选择“中国移动” |

通常只需填写学号，不必手工拼接前缀或后缀。程序会根据所选服务添加 `@cmcc`；已填写该后缀时不会重复添加。电脑端账号前缀由门户配置决定，当前现场格式为 `,0,学号@cmcc`，无需手工填写 `,0,`。

### 2. 选择连接方式

在“高级选项”中设置“通过路由器连接”：

| 电脑接入方式 | 选项设置 |
| --- | --- |
| 电脑通过 Wi-Fi 或网线连接宿舍路由器，路由器接入校园网 | 勾选“通过路由器连接” |
| 电脑直接连接校园网，不经过宿舍路由器 | 取消勾选，使用直连模式 |

新配置默认勾选路由器模式。旧配置缺少该设置时会保留直连方式；升级用户通过路由器接入时，需要自行勾选。

路由器模式会访问 `http://a.njtech.edu.cn/` 获取出口身份和门户配置。直连模式使用“Portal IP”设置，默认地址为 `10.255.20.10`，端口为 `801`。如需修改 Portal IP，只填写 IPv4 地址，然后点击“应用”；不要在输入框中填写协议或端口。

### 3. 保存并登录

1. 勾选“自动保活与重连（每30秒检测）”。
2. 点击“保存账号”，日志会显示“账号信息已加密保存”。
3. 程序按保存的配置进行检测；需要认证时自动尝试登录。也可以点击“一键登录”立即发起登录操作。
4. 等待顶部状态显示“已在线”，再打开浏览器访问外网，确认实际联网。

点击“一键登录”也会先保存当前填写的账号。修改用户名、密码或服务后，应点击“保存账号”或“一键登录”，让自动监控使用新配置。

如果已通过浏览器登录，程序检测到外网在线后会继续探测，不会为了保活重复登录。

### 4. 保持运行

完成登录后，可以点击窗口右上角的关闭按钮，程序会继续在系统托盘运行。保持电脑开机、网络连接和程序运行，即可持续检测并按需重新认证。

## 日常操作

| 操作 | 作用和注意事项 |
| --- | --- |
| 一键登录 | 保存当前账号，提交手动登录任务；用于首次连接或恢复主动暂停的认证 |
| 刷新状态 | 重新检测网络和门户状态，不强制注销 |
| 保存账号 | 保存用户名、密码和服务，更新监控配置 |
| 自动保活与重连 | 开启或关闭自动检测与认证；关闭后仍可手动登录 |
| 注销 | 暂停自动认证，再注销当前出口 |
| 注销并重新登录 | 串行注销当前出口、刷新身份并重新认证，会短暂中断网络 |
| 本机下线 | 与注销一样，先暂停自动认证 |
| 关闭窗口 | 隐藏到托盘，程序继续运行 |
| 退出程序 | 停止监控并退出进程 |

**主动注销后，点击“一键登录”才能恢复自动认证。** 在同一次运行中，仅保存账号或重新勾选自动选项不会解除主动暂停。密码错误、账号停用或套餐异常导致的暂停，则可在修正账号/套餐后，通过保存配置或手动登录恢复。

### 托盘操作与退出

- 双击托盘图标，或右键选择“打开主界面”，恢复窗口。若图标被隐藏，可先展开任务栏通知区。
- 右键托盘图标选择“退出程序”，或点击窗口内的“退出程序”，才能真正结束运行。
- 退出时程序会等待正在进行的请求结束，然后停止后续请求并清理资源。
- 程序已运行时再次启动，会提示已有实例。先从托盘打开现有窗口，不必重复启动。
- 独立命令行监控运行时，先停止它，再打开图形界面修改配置。

程序不会自动创建开机启动任务；重启电脑后需重新运行工具。关闭 GUI 后也不会额外创建一个独立后台进程。

## 如何理解状态提示

只有外网复测通过才显示“已在线”，门户接受认证并不等于外网已经恢复。

| 状态或提示 | 含义 | 建议操作 |
| --- | --- | --- |
| 已在线 | 外网连通性检测通过 | 保持程序运行 |
| 需要认证 | 已确认当前出口尚未认证 | 确认账号已保存并开启自动选项，或点击“一键登录” |
| 未提交认证 | 身份、配置或认证状态无法确认，尚未提交账号认证 | 查看提示和日志，检查网络及连接模式 |
| 认证失败 | 已提交认证，但门户拒绝或认证失败 | 按提示检查密码、服务和套餐 |
| 认证已接受，等待外网恢复 | 门户已接受认证，但外网复测未通过 | 等待后续检测，确认学校或运营商网络是否正常 |
| 网络故障 | 当前检测表明存在网络问题 | 检查物理连接、路由器及外网状态 |
| 状态未知 | 门户查询无法提供足够的判断依据 | 查看日志，稍后刷新状态 |
| 已注销／自动监控已暂停 | 已主动注销，自动认证保持暂停 | 需要恢复时点击“一键登录” |

## 自动保活与重连机制

在线时程序默认每 30 秒发送探测，不重复认证；单个探测地址失败会尝试其他地址。全部外网探测失败后，程序查询门户，并按当前出口 IP 匹配在线记录，查询成功码本身不代表已认证，合法空列表表示需要认证。

在线列表无法确认时，南京工业大学路由器模式会继续通过门户内核核验出口状态。确认未认证或发现外网明确重定向到校园门户时，才按需认证；已认证但外网故障时继续检测，两种查询均无法确认时保持“状态未知”。

临时失败后的等待间隔为 30、60、120、240、300 秒，最长 300 秒；恢复后回到正常的 30 秒间隔。账号错误会暂停自动认证，避免反复提交错误账号。

路由器模式每次认证都会刷新出口身份，不使用电脑局域网 IP/MAC 替代。已知南京工业大学路由器协议缺少真实 MAC 时，使用门户支持的全零 MAC 占位值；有真实 MAC 时优先使用真实值。出口 IP 缺失、身份格式异常或冲突、门户配置无法解析时，程序拒绝提交并显示原因。

## 配置、日志与更新

### 配置保存在哪里

配置文件：

```text
%USERPROFILE%\.campus_net_login\config.json
```

在文件资源管理器地址栏输入 `%USERPROFILE%\.campus_net_login` 即可打开配置目录。账号设置与 EXE 位置无关，更新程序无需重新创建配置。

密码使用 Windows DPAPI 加密，由当前 Windows 用户解密。更换电脑或 Windows 用户后，不应依赖直接复制配置恢复密码，应在界面重新输入并保存。

配置中的 `auto_maintain` 和 `router_mode` 分别保存自动监控和路由器选项，重启后保留服务和选项。旧版任一自动选项开启会迁移为 `auto_maintain=true`，两项都关闭则保持关闭。

### 查看日志

监控日志：

```text
%USERPROFILE%\.campus_net_login\logs\monitor.log
```

日志最多保留当前文件和 3 个历史文件，记录掉线发现时间、认证状态、退避间隔和恢复耗时。离线时记录探测、在线列表计数和门户内核状态摘要；无法确定原因时标记“未知”。

监控日志不保存原始在线记录、账号、密码或包含密码的请求 URL，可能包含出口 IP/MAC，分享前可遮盖这些设备信息。界面日志可能显示已加载的账号，分享窗口截图时也应遮盖账号。

### 更新 EXE

1. 从托盘或主窗口选择“退出程序”，等待进程结束。
2. 下载新版本 `CampusNetLogin.exe`，替换原文件。
3. 重新运行，检查用户名、服务、路由器模式和自动选项是否正确。
4. 查看状态和日志，确认外网检测正常。

不要在旧程序仍运行时直接覆盖 EXE。保留同一 Windows 用户目录下的配置即可延续设置。

## 常见问题

### 点击关闭后为什么还在运行？

窗口右上角的关闭按钮用于隐藏到托盘。需要停止保活时，从托盘菜单或窗口点击“退出程序”。

### 没打开浏览器，工具能自动登录吗？

已保存有效账号、开启自动选项并连接校园网时，程序启动后会立即检测；确认需要认证后自动登录，无需先打开浏览器。未保存账号时，应先完成首次配置。

### 显示状态未知或未提交认证怎么办？

先确认电脑仍连接校园网，再核对“通过路由器连接”是否符合实际接入方式。尝试在浏览器打开 `http://a.njtech.edu.cn/` 检查门户能否访问，然后查看日志和状态详情。若出口身份、门户配置或查询状态无法确认，工具会保持未知并拒绝提交认证。

### 认证已接受，为什么仍然不能上网？

该提示只表示门户接受认证，外网检测仍失败。等待下一轮检测，并检查浏览器是否能访问外网、路由器是否正常，以及校园网或运营商是否存在故障。

### 密码错误或套餐异常后不再重连怎么办？

先确认统一身份认证密码、所选服务和运营商绑定状态，修正后点击“保存账号”或“一键登录”，解除账号错误导致的暂停。

### 注销后重新勾选自动选项，为什么没有登录？

主动注销会在当前进程中保持暂停。点击“一键登录”恢复；保存账号或切换自动选项不会解除该暂停。

### 电脑在线，手机却不能上网怎么办？

先确认手机与电脑连接同一个宿舍路由器，并确认电脑启用了路由器模式。再检查路由器和学校对多设备接入的要求。电脑外网检测成功只能证明电脑当前在线，手机共享联网需要单独检查。

### 能保证一直不掉线吗？

不能。学校强制到期、运营商故障、电脑睡眠或程序退出都可能中断网络。工具会在运行期间检测故障，并在确认需要认证时尝试恢复。

## 源码运行

当前桌面版本仅支持 Windows。已验证的源码环境为 Python 3.9.13 x64、Tk 8.6，具体工具链见 [验证记录](docs/EVIDENCE.md)。安装 Python 时应包含 Tkinter。

在 PowerShell 中执行：

```powershell
git clone https://github.com/GmdsSeikai/nanjing-tech-university-campus-network-keepalive.git
cd nanjing-tech-university-campus-network-keepalive
python -m venv build/.venv
.\build\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\build\.venv\Scripts\python.exe app.py
```

`build/.venv` 为本地运行与构建环境，该目录已由 Git 忽略，无需激活即可使用上述命令。先在图形界面保存账号和连接选项，再使用命令行模式。

### 持续监控

```powershell
.\build\.venv\Scripts\python.exe app.py --monitor
```

该模式不打开 GUI，使用保存的配置持续检测。在控制台按 `Ctrl+C` 停止。关闭自动选项后不会自动认证；不会新增开机任务或 Windows 服务。

### 单次检测与按需认证

```powershell
.\build\.venv\Scripts\python.exe app.py --once
$LASTEXITCODE
```

`--once` 执行一次检测，在已保存账号且确认需要认证时尝试登录，然后退出。该显式单次操作不受自动监控开关关闭的限制。

| 退出码 | 含义 |
| --- | --- |
| 0 | 外网已验证在线 |
| 1 | 本轮未恢复在线 |
| 2 | 已有 GUI 或监控实例运行，本次未执行检测 |

源码和 EXE 使用同一套配置及单实例锁，不要同时运行它们。EXE 也接受 `--monitor` 和 `--once` 参数；需要观察控制台输出或用 `Ctrl+C` 停止持续监控时，使用上述 Python 命令。

## 从源码构建与验证

在仓库目录的 Windows PowerShell 中运行：

```powershell
.\build.bat
```

脚本会创建 `build/.venv` 隔离环境，安装运行及构建依赖，执行测试和编译检查，再通过 PyInstaller 生成 `release/CampusNetLogin.exe`。构建工具版本见 [requirements-build.txt](requirements-build.txt)。

完整本地验收入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_windows.ps1
```

该入口执行构建、源码检查以及实际 EXE 的托盘、单实例锁和退出检查。产物检查使用临时空账号配置，只读探测外网，因此需要当前已联网；未联网时会明确失败。它不会使用实际保存的密码认证。

## 现场验证与使用边界

自动重新认证已由用户现场确认成功。手机共享、完整的退出后到期重启流程和连续 24 小时观察仍需分别验收；一次自动恢复或一天观察不能证明永久不掉线。

可按以下步骤检查自己的环境：

1. 使用工具认证，确认电脑能够访问外网；如需手机共享，再检查同一路由器的手机。
2. 退出工具，等待校园认证自然到期。确认连接失效后重新运行，保留正确服务、路由器模式和自动选项，观察无需浏览器操作时能否恢复。
3. 持续运行至少 24 小时，包含夜间闲置，查看日志中的掉线与恢复时间。
4. 检查主动注销后保持暂停、托盘运行时继续监控、退出后停止检测。
5. 如出现密码或套餐错误，先修正账号或绑定状态，再保存配置或手动登录。

验证范围和已执行命令见 [docs/EVIDENCE.md](docs/EVIDENCE.md)，实现规格见 [docs/SPEC.md](docs/SPEC.md)，Windows 更新与交付说明见 [README_DEPLOY.md](README_DEPLOY.md)。

主要修改包括南京工业大学 Dr.COM 门户适配、中国移动与宿舍路由器出口认证、自动保活与到期重认证、系统托盘与单实例控制、Windows DPAPI 密码保护，以及对应测试和 Windows 打包验证。

原仓库的移动端与远程控制代码保留在 `mobile_app/`、`remote_control/` 等目录，桌面保活工具无需运行这些组件。
