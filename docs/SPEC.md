# 中国移动与路由器保活实施规格

授权依据：用户要求直接实施所附《中国移动登录与路由器保活改造方案》。本规格落实该方案，不增加发布、真实认证或远程写入授权。

spec approval: not obtained (autonomous run)。用户授权实施计划，未另行逐字审批本规格；验证结论限定于实际执行的本地及产物检查。

- 服务新增中国移动；后缀去重，按现场 `account_prefix` 组成电脑端前缀。
- 旧配置 `auto_keepalive OR auto_reconnect` 迁移到 `auto_maintain`；旧配置默认直连，新配置默认路由器连接。密码继续使用 DPAPI。
- 路由器模式从宿舍门户 URL、未注释页面变量和只读在线结果获取出口身份，禁止回退到本机身份。每次认证刷新；缺少出口 IP 或页面认证配置时拒绝提交密码。
- 连通性成功需匹配状态码和内容；单个探测失败不触发认证。全部失败后仅明确校园门户重定向或在线接口明确未认证才能提交。
- 接口成功必须再次验证外网；四态为 online、need_login、network_error、unknown。无伪造会话索引。
- 统一监控器拥有一个工作线程，串行检测、手动认证和注销。每 30 秒保活；失败等待 30/60/120/240/300 秒；永久账号错误暂停自动认证，配置更新或手动登录恢复。主动注销暂停，保存配置和开关不能解除该暂停。
- GUI 与后台入口持有同一个 Windows mutex；暂停与停止可取消等待及尚未发出的认证。已发送 HTTP 请求等待有界结束后才能销毁窗口/释放单实例锁。主线程队列接收 UI 消息。
- 窗口关闭进入托盘，退出停止工作。日志记录发现时间、状态、重试、恢复耗时；不得泄露密码或密码请求 URL。

失败模型：出口身份错误、门户假阳性、探测单点失败、认证后仍无法上网、永久错误导致反复认证、暂停时迟到认证、重复线程、停止后 UI 访问、双进程并发。

验证：unittest 覆盖上述边界、旧服务和配置；真实 Windows Tk/托盘及 mutex；只读现场上下文查询；PyInstaller 构建及打包启动。真实密码认证、手机共享和 24 小时夜间观察由现场验收完成，不能由模拟测试替代。

新增运行依赖：无。构建工具：PyInstaller。持久交付：源码、测试、使用说明、规格/决策/验证记录和 Windows EXE；不创建开机任务、不修改路由器/手机/远控。

## 2026-10-06 修订：到期后自动认证

授权依据：用户要求直接实施《修复路由器到期后无法自动认证》计划。该计划授权源码、回归测试、规格与决策更新、重建交付 EXE 和哈希检查。spec approval: not obtained (autonomous run)。不增加依赖、不修改保存的账号或路由器、不主动注销现场会话；真实到期恢复由现场验收。

- 南京工业大学 `drcom_new` 路由器协议中，页面和只读身份查询都缺少真实 MAC 时，使用门户的 `000000000000` 占位值；页面的全零和 `111111111111` 未知值归为缺失。真实 MAC 存在时优先使用。仍要求有效的当前出口 IPv4；异常格式、多个来源的 IP/MAC 冲突必须在提交密码前拒绝。不回退到本机身份、不缓存旧出口身份，其他协议不启用此例外。
- `online_list.result=1` 只表示查询成功。必须有合法 `list` 和一致的非负整数 `total`；记录按 `online_ip` 匹配当前出口。匹配时为已认证但外网故障；完整列表没有当前出口（含 `list=[]`、`total=0`）为需要认证。字段缺失、类型异常、计数矛盾、记录 IP 异常和任意查询错误保持未知。`chkstatus` 的状态码语义保持独立。
- 外网没有成功探测，且明确重定向到已知校园认证门户时，保留 `redirect_url` 并进入需要认证状态；在线查询成功码不能覆盖此证据。身份验证仍是提交前置条件。
- `LoginResult.phase` 为 `not_submitted`、`failed`、`accepted` 或 `online`。界面分别显示“未提交认证”“认证失败”“认证已接受，等待外网恢复”“已在线”；自动与手动认证都传递该结果。认证已接受但外网验证抛错仍保留 `accepted`，只有外网验证通过才令 `success=true`。
- 打开工具立即检测；保存中国移动账号且开启自动监控时按需提交一次认证并验证恢复。保留现有退避、永久错误暂停、主动注销暂停、退出停止和单实例行为。

失败模型与证据：模拟 HTTP 边界执行生产 API、监控启动及 Windows Tk，覆盖无 MAC 到期恢复、真实 MAC、空列表、其他出口、缺失/矛盾响应、门户重定向、错误密码、已认证但外网故障、身份异常/冲突、取消与退出。使用现有 `scripts/verify_windows.ps1` 执行源码测试、编译、构建和真实 EXE 工作流；检查交付与桌面文件 SHA256。模拟恢复和只读查询不能代替“退出工具→会话到期→重新打开→电脑与手机联网”的真实现场验收。

## 2026-10-06 补充修订：独立核验未知认证状态

用户反馈修正版仍停在“未提交认证：外网探测失败，门户认证状态未知”。现场日志记录该状态，但原日志未保存查询摘要；再次只读检查时外网已经恢复，无法据此确定失败时的 `online_list` 响应。学校 `a41.js` 将 `/drcom/chkstatus.result=0` 作为未认证状态，工具读取该接口身份后却未在列表未知时利用其认证证据。

- 仅在已确认的南京工业大学 `drcom_new` 路由器协议中，`online_list` 不可解析为认证状态或查询失败时，重新只读请求当前出口的 `/drcom/chkstatus`。校验该次响应与已刷新出口 IP/MAC 无冲突后，`result=0` 表示未认证、`result=1` 表示已认证；无需依赖响应中文消息。身份冲突、未知状态码、查询失败仍保持未知，不提交。
- 列表明确匹配当前出口时继续阻止重复认证；未知列表自身不能授权认证，需独立内核证据或已确认的认证重定向。两种查询都无法确认时仍退避等待。
- 界面诊断及离线监控日志保存在线列表和内核状态的脱敏摘要（结果码类别、列表类型/条数、计数与判定），不保存原始记录、账号、密码或请求 URL。已在线时不增加正常探测日志。
- 新增生产路径回归：无 MAC、无重定向、未知/失败的在线列表 + 内核离线应提交并恢复；内核在线但外网故障不认证；两者未知不认证；独立核验身份冲突不认证。保留全部原生命周期断言。

授权为继续完成用户要求的修复与交付；spec approval: not obtained (autonomous run)。主动注销真实会话仅在用户单独明确允许后执行；该询问不阻止本地修复、构建和只读核验。
